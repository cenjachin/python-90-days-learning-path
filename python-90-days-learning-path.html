常见坑与避坑指南

这些坑 90% 的初学者都会踩，提前知道就能少交一半学费。

坑现象正确做法
Tab/空格混用IndentationError统一 4 个空格；VS Code 开启「渲染空格」和自动转换
只看不写看懂了，写不出当天内容亲手敲一遍；抄完要改参数、改结构再跑
抄代码不理解一报错就慌每行问自己「这行在干嘛」；跑通后故意改坏，观察报错
遇到报错就放弃卡住半天，心态崩先读最后一行错误信息 → 复制关键信息搜索 → 前人基本都踩过
不用虚拟环境包装不上、版本冲突每个项目一个 venv，pip install 前先激活环境
中英文标点混淆SyntaxError: invalid character代码里一律用英文标点（引号、冒号、括号、逗号）
文件编码乱码打开中文文件乱码open() 时加 encoding="utf-8"
变量命名混乱a, b, x, tmp 满天飞有意义的英文名 + snake_case
不写注释一周后看不懂自己代码关键逻辑写注释，函数写 docstring
囤课不开始收藏 = 学会选定一个主教程，今天就开始
盲目追新追全同时学 3 个框架一个阶段只用一套工具，跑通再换
完美主义迟迟不敢交付先跑起来再优化；90 天看进步，不看好坏
中断后自责断更 3 天就全盘放弃落后时砍练习量、保里程碑；周末补，不要从 Day 1 重启

坚持学习的 5 个技巧

01
固定时间

每天同一时段（如 20:00–22:00），形成习惯的条件反射

02
输出倒逼输入

每周写一篇学习笔记，博客 / 朋友圈 / 备忘录都行

03
加入社区

找个学习群或拉上朋友，卡住时有人问、想放弃时有人拉

04
项目驱动

Week 3 后就琢磨「我想做个什么」，带着问题学

05
允许不完美

代码丑没关系，能跑就先提交，后面再优化

里程碑打卡

原则：里程碑 > 知识点 > 练习量。到了日子先检验里程碑，再决定要不要补细节。

完成进度0 / 5
10

如果落后了怎么办

缺 1–2 天

周末补，优先保「里程碑」，不保「每日计划」。

缺 3 天以上

砍练习数量，不砍知识点；Phase 4/5 各砍 1 天打磨时间。

落后超过 1 周

把 Week 13 当缓冲周，整体顺延而非重来。

总原则

里程碑 > 知识点 > 练习量。永远不要从 Day 1 重启。

90 天不会让你变成专家，但会让你建立「我能用代码解决问题」的信心。这种信心比任何知识点都重要。
